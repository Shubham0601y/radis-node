# radis-node

Official Node.js remote SDK for the Radis cache API. This SDK sends requests to the Radis server; it does not create or use a local NodeCache instance.

## Requirements

- Node.js 18 or newer (native `fetch`)
- A client key generated by your Radis application

## Install

```bash
npm install radis-node
```

Until the package is published, install from the local folder or a Git repository:

```bash
npm install github:YOUR_GITHUB_USERNAME/radis-node
```

## Configure

The Radis API hostname is built into the SDK. Customers do not need to provide `baseURL` or `RADIS_BASE_URL`.

Keep the client key on your backend only. Do not expose it in browser JavaScript, React, or a `VITE_*` environment variable.

```env
RADIS_CLIENT_KEY=your-encrypted-client-key
```

```js
import Radis from "radis-node";

const myCache = new Radis({
  clientKey: process.env.RADIS_CLIENT_KEY,
  timeout: 10_000,
});

export default myCache;
```

## Usage

All methods are asynchronous because the SDK communicates with the Radis server over HTTP. Always use `await`.

```js
await myCache.set("user:101", { name: "Asha", active: true }, 3600);

const user = await myCache.get("user:101");
console.log(user); // { name: "Asha", active: true }

const exists = await myCache.exists("user:101");
const remaining = await myCache.ttl("user:101");

await myCache.persist("user:101");
await myCache.del("user:101");
```

### Available methods

| Method | Result / behavior |
|---|---|
| `set(key, value, ttl = 0)` | Store a JSON-serializable value |
| `get(key)` | Value, or `null` if missing |
| `getWithMetadata(key)` | `{ key, value, ttl }`, or `null` if missing |
| `del(key)` / `delete(key)` | `true` if deleted, otherwise `false` |
| `exists(key)` | Boolean |
| `type(key)` | Type string returned by the API |
| `ttl(key)` | `null` missing, `0` persistent, otherwise remaining seconds |
| `persist(key)` | Remove expiration |
| `rename(key, newKey)` | Rename a key |
| `copy(key, newKey)` | Copy a key |
| `mset(values, ttl = 0)` | Set multiple key/value pairs with one TTL |
| `mget(keys)` | Array of records returned by the API |
| `mdel(keys)` | Number of keys deleted |
| `expireMultiple(keys, ttl)` | Set expiration on multiple keys |
| `entries()` | Current tenant's entries returned by the API |

### Multiple values

```js
await myCache.mset(
  {
    "user:101": { name: "Asha" },
    "user:102": { name: "Ravi" },
  },
  3600,
);

const users = await myCache.mget(["user:101", "user:102"]);
const deletedCount = await myCache.mdel(["user:101", "user:102"]);
```

### Error handling

```js
import Radis, { RadisError, RadisNetworkError } from "radis-node";

try {
  await myCache.set("session:1", { userId: 101 }, 900);
} catch (error) {
  if (error instanceof RadisError) {
    console.error(error.message);
    console.error(error.status);
    console.error(error.details);
  } else if (error instanceof RadisNetworkError) {
    console.error("Could not reach Radis", error.cause);
  } else {
    throw error;
  }
}
```

### Per-request abort

Every method accepts an optional final options object with an `AbortSignal`:

```js
const controller = new AbortController();
const pending = myCache.get("user:101", { signal: controller.signal });
controller.abort();
await pending;
```

## TTL rules

TTL is always in seconds, matching the current Radis NodeCache implementation:

- `0`: no expiration
- Positive integer: expire after that many seconds

## API hostname management

The API hostname is configured centrally in `src/config.js`. Customers do not pass it during SDK initialization.

If the public Radis API hostname changes, update `RADIS_API_BASE_URL` in `src/config.js`, publish a new SDK version, and keep the old hostname redirecting or proxying during the migration where possible. Existing installed SDK versions retain the hostname they were published with.

For infrastructure changes without forcing customers to update the SDK, keep a stable API hostname and change its DNS or reverse-proxy destination instead.

## Current API scope and known server-side follow-ups

This SDK exposes only operations present in the inspected Radis customer routes. It does not add `flush`, single-key `expire`, Redis data structures, or pagination because those customer endpoints are not currently present in the backend route file.

Before production use, fix the current `/get/:key` controller so it preserves falsy values (`false`, `0`, and `""`) instead of converting them to `null`. It should use `value === undefined ? null : value`. The current `entries()` endpoint should gain server-side pagination before tenants accumulate large numbers of keys.

The SDK does not automatically retry requests: retrying mutations after a timeout can cause ambiguous outcomes.
